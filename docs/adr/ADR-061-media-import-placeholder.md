# ADR-061 · 大文件导入：先占位、后台加密

> 状态：已采纳。关联：[ADR-052](ADR-052-media-album-hub.md)（媒体导入）、
> [ADR-055](ADR-055-editor-video-audio-blocks.md)（编辑器媒体块）、
> [ADR-058](ADR-058-large-media-key-cache-and-streaming-playback.md)（大文件性能）、
> [ADR-059](ADR-059-media-picker-mode-and-audio-list.md)（选择器）。

## 一、问题

ADR-058 解决了「每 1 MiB 重新取密钥」和「整份解密后播放」，但**导入本身**仍然是
同步等待：用户选完一个大视频后，编辑页要等整份文件复制 + 加密完成，才能看到卡片、
才能保存、才能继续插入另一个文件。600 MB 视频意味着编辑被占用几十秒到几分钟。

对用户来说，写入中的正文和「再存一个文件」这两件事完全不该被一个后台加密任务挡住。

## 二、决策

### 1. 先插占位，再后台加密

选择器（内置独立页面或系统选择器）**只回传设备 URI**，立刻返回编辑页。宿主随即：

1. 为每个 URI 生成一个临时的 32 位十六进制占位 id；
2. 立刻把 `![](meteor://media/<占位 id>)` 追加进正文；
3. 在后台用 `MediaImporter` 加密落库；
4. 成功后把占位 id 原地替换成真实 id，失败则删掉这一行并提示。

占位 id 与真实 id 同形（32 hex），因此 Markdown 解析、`MediaRef` 规则、数据结构都不需要
新格式；「它是否还在导入」只由宿主内存里的 `pendingMedia` 集合决定。

### 2. 新增渲染状态 `MediaBlockState.Importing`

编辑器把它画成「正在导入…」的中性卡片（与 `Pending` 的「正在载入…」区分）：

- `Pending` = 宿主还没解析出来（读元数据中）；
- `Importing` = 文件正在被加密写入，卡片下方不可出现「删除」按钮，避免删掉占位后
  留下一份没有引用的孤儿文件。

### 3. 后台导入串行，编辑不阻塞

- 宿主维护一个 `Mutex`，多个占位对应的导入**串行**执行，避免几个大文件同时抢 IO；
- 占位卡片在排队期间已经显示，用户能继续打字、继续点「插入」再选文件；
- 工具栏的「插入」只在**旧的同步图片插入**进行时禁用，后台媒体导入不再禁用；
- **保存按钮在仍有占位未完成时禁用**（`isInserting` 含 `pendingMedia`），因为此时正文
  里的 id 还不是真实媒体；保存会写出一个指向不存在文件的引用。

### 4. 选择器不再负责导入

ADR-059 里独立选择器页面会自己导入并把媒体 id 回传。现在改为**只回传 URI**，
导入统一由宿主的占位队列完成。两种选择器模式（内置 / 系统）因此走同一条路径，
日记与人物编辑行为一致。

## 三、R1 四问

1. **模块**：`:feature-editor` 新增 `MediaBlockState.Importing` 与
   `MarkdownEditing.replaceMediaId`；`:app` 的三个编辑器 ViewModel 增加占位队列。
   不新增模块。
2. **依赖**：无新增模块边。
3. **接口**：`MarkdownEditing.replaceMediaId` 是新增纯函数；`MediaBlockState` 是
   sealed interface，新增分支后所有 `when` 已同步补全（目前在 `MarkdownMediaBlock`
   一处）。`DiaryEditorState` / `PersonEditState` 新增带默认值的 `pendingMedia`。
4. **数据格式**：不变。占位引用与真实引用同形，档案、备份、索引都无需感知占位；
   保存时若仍有占位会被拒绝，所以磁盘上不会出现悬空引用。

## 四、后果

- 大文件导入不再冻结编辑：卡片先出现，用户可以继续写、继续添加。
- 导入失败的占位行会被移除并给出一次错误提示，不留下坏引用。
- 若用户在导入完成前离开编辑页，ViewModel 被销毁、导入取消，正文未保存的占位随之消失；
  已经落盘的媒体（若导入已成功但页面已离开）会留在相册里，可手动删除。
- 串行队列意味着第二个大文件要等第一个完成才真正开始处理，但占位已可见，
  不会让用户误以为没反应。
