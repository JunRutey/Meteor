# ADR-025 · AI 工具面：读写分级与「周/年档案代写」预留

- 状态：已接受（v0.6.2）
- 日期：2026-10-31
- 关联：ADR-024（联网 AI、只读工具、隐私边界）

## 背景

v0.6.1 的 AI 只能读档案。用户希望「把应用内已实现的功能都开放成 AI 的接口」，
并明确提出未来要能根据每天的心情与日记，一键生成周记 / 年记。
这需要区分「读」「写」「不可逆」三类能力，并为摘要类功能预留稳定接口。

## 决定

### 1. 读写分级

- **读工具**：默认开启，无需额外同意。包含档案检索、人物、记录、日记日期、心情。
- **写工具**：只有用户在设置里打开「允许 AI 修改档案」后，请求里才会带上写工具。
  当前开放 5 个：
  - `save_diary(date, body)` / `append_diary(date, text)`
  - `set_mood(date, mood)`
  - `create_person(name, relation, notes)` / `update_person(person_id, name, relation, notes)`
- **不可逆操作永不开放**：删除记录、清空档案、备份导出/导入、修改 API Key、开关应用锁。
  这些即使打开写开关也不会出现在工具列表里。
- 写工具的执行不弹二次确认（对话里逐条确认会破坏体验），改为：
  写开关本身是显式同意；系统提示要求模型在回复里说明具体日期与改动；
  所有写在 UI 侧可继续用现有编辑页查看与撤回。

### 2. 工具面与模块边界

- 工具实现留在 `:feature-ai`（`ArchiveTools`），依赖的写接口来自 `:core-storage`
  （`DiaryQueries` / `MoodQueries` / `PersonQueries`），仍然单向依赖。
- 新增功能若要给 AI 用，必须先在 `:core-storage` 暴露窄接口，再由 `ArchiveTools`
  注册工具；不允许 AI 模块直接碰文件、Keystore、网络或导出。

### 3. 为「周/年档案代写」预留

未来版本（v0.7+）计划：

- 新增 `DigestSource` 概念（周/月/年），输入是一段时间内的日记、心情与人物提及，
  输出是一份可编辑的摘要草稿，**不直接覆盖任何已有记录**。
- 复用现有只读工具与 `dateContext`；摘要生成走同一套「本地取数 + 只发送片段」的流程。
- 需要的新接口：`DiaryQueries.range(from, to)`（本期未加）、`MoodQueries.range`（已有）、
  以及「摘要草稿」的独立存储（加密、非档案正文）。
- 该功能不进入 v0.6.x；本期只保证：时间窗解析、按日期取数、写开关、工具注册方式已经就位。

## 后果

- AI 能完成更多「帮我写下来」的任务，但删除/导出这类不可逆能力保持不可达。
- 写工具扩大了 prompt injection 的潜在影响面；缓解：默认关闭、工具白名单、无删除、
  回复必须说明改动、用户仍可在编辑页覆盖。
- 未来新增工具时，必须同时更新本 ADR 的清单与 README 的工具数量。
