# ADR-033 · 每日日记提醒与通知渠道

- 状态：已接受
- 日期：2026-11-07
- 关联：ADR-013（设置持久化）、ADR-032（AI 功能边界）

## 背景

用户需要在每天尚未写日记时收到提醒，并希望通知权限只在主动启用功能时申请。未来应用内置 AI 也需要有独立的通知渠道，但本次不接入 AI 消息生成或发送。

## 决定

### 模块边界

- 新增 `:core-notify`，定义日记提醒和 AI 消息通知渠道、闹钟调度器，以及不依赖 Android UI 的纯逻辑提醒策略。
- `:app` 负责 Hilt 组装、系统权限流程、通知展示、日记状态查询及闹钟恢复；新增依赖边 `app → core-notify`。
- `:feature-settings` 继续负责偏好数据和设置 UI。提醒默认关闭，时间以本地午夜后的分钟数保存，默认值为 20:00。
- AI 通知渠道本次只创建、不发送；未来 AI 只能使用独立渠道，不与日记提醒共用。

### 调度与权限

- 提醒触发时检查本地当天是否有日记；已有日记则不显示通知。
- 优先使用 `AlarmManager.setExactAndAllowWhileIdle`。若未授予精确闹钟权限或授权在调度期间被撤销，则回退至 `setAndAllowWhileIdle`，设置页说明精度降级并提供授权入口。
- `POST_NOTIFICATIONS` 仅在用户开启提醒时请求；拒绝时不持久化开启状态，开关保持关闭并解释原因。
- 每日提醒同时检查应用级通知权限与日记提醒专属通知渠道；渠道被关闭时暂停调度，并从设置页直达该渠道设置，避免把“应用通知已允许”误判为提醒可显示。
- 用户关闭提醒后取消闹钟；开关、时间变化、重启、时区或系统时间变化及应用更新后同步调度。

### R1 模块准入五问

1. **模块归属：** 新建 `:core-notify`；设置偏好和界面归现有 `:feature-settings`，平台生命周期、通知展示和 DI 归 `:app`。
2. **依赖方向：** 只有 `:app → :core-notify`；`core-notify` 不依赖存储、设置或 Hilt，日记查询由 app 组合层传入。方向单向、无环，依赖边同步登记在 `tools/check-module-graph.sh`。
3. **对外接口：** 核心层仅暴露渠道标识、按日期判断是否提醒、下一次本地触发时间及调度操作；策略纯逻辑、可单测。
4. **可移除性：** `:core-notify` 没有其他模块依赖；app 以可选模块 source set 绑定真实实现或无操作实现。排除核心模块不影响其余模块编译、日记读取或既有偏好读取。
5. **数据格式：** 不修改日记或既有档案格式。新增 DataStore 键的缺省值为关闭和 20:00，不需迁移并向后兼容。

## 后果

- Android 13 及以上不会因安装或首次启动而自动弹出通知授权；只有用户主动开启提醒时才请求。
- 精确闹钟授权不是提醒可用性的硬前提，未授权时仍会以非精确方式运行。
- 创建 AI 消息渠道为后续功能预留系统设置入口，但当前没有 AI 发送能力或额外网络行为。
