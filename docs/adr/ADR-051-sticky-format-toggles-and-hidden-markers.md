# ADR-051 · 格式按钮改为粘滞开关，编辑区隐藏行内标记

- 状态：已接受（v1.4.0）
- 影响：`:feature-editor`（新增 `MarkdownInlineRendering`、`MarkdownInlineEditing`，
  改动 `EditorToolbar`、`MarkdownField`）
- 关联：ADR-021（编辑区退回纯文本）、ADR-048（工具栏恢复加粗与彩色字体，
  **一次性插入语法**）
- 关系：本文**部分取代 ADR-048 的交互方式**（一次性包裹 → 粘滞开关），
  并且**推翻了 ADR-021 的「不隐藏标记」结论**。ADR-048 的数据格式与
  `MarkdownInlineFormat` 保留不变。

## 一、背景

ADR-048 把加粗与颜色做成**一次性命令**：选中文字 → 点按钮 → 标记插入 → 结束。
编辑区按 ADR-021 的规矩逐字显示 `**` 与 `<span …>`。

用下来有两个问题：

1. **交互不符合写作节奏。** 真实习惯是「先决定要强调，再打字」，
   而不是「先打字、选中、再点按钮」。空选区时 ADR-048 插入 `****` 把光标放中间，
   但用户看到的是四个星号，不知道该接着打字还是先删掉它们。
2. **标记噪音。** ADR-048 已知限制第 1 条写的就是这一点：写长文时正文里
   满是语法噪音。

用户的诉求很明确：

> 点击加粗，加粗按钮就把选中，这时输入文字就加黑加粗，再点击按钮，取消选中，
> 结束加黑加粗功能。颜色那个同样逻辑，选中颜色后图标变成相应颜色，被选中。
> 此时输入文字就是相应颜色，再点击结束该功能。
>
> 隐藏标记。

## 二、决策

### 2.1 按钮是模式开关，不是一次性命令

`InlineFormat` 表示「当前开着的格式」，由 `MarkdownField` 持有：

```kotlin
sealed interface InlineFormat {
    data object Bold : InlineFormat
    data class Color(val hex: String) : InlineFormat
}
```

- 点 `B` → `activeFormat = Bold`，按钮点亮（`secondaryContainer` 底），
  此后输入的文字就是粗体；
- 再点 `B` → `activeFormat = null`，按钮恢复，结束加粗；
- 点某个色点 → `activeFormat = Color(hex)`，**颜色按钮的图标变成该色实心点**，
  输入即为该色；再点同一个色点结束；
- 点另一个色点 → 直接切换（先收口旧 run，再开新 run），**绝不嵌套两层 span**。

旧的一次性行为没有丢：**如果点按钮时存在选区，就先就地包裹选区**，
然后模式仍然保持开启，光标落在 run 末尾继续打字。两种习惯都能用。

### 2.2 标记隐藏，但数据不变

新增 `MarkdownInlineRendering`（`VisualTransformation`）：把 `**` 与
`<span style="color:#RRGGBB">`、`</span>` 从**显示文本**里去掉，
把被包裹的文字直接画成粗体/彩色。

**存储的字符串一个字节都没变**——隐藏只发生在渲染层。这一点是硬约束：
明文备份、`:core-index` 全文检索、AI 读取、旧版本 app 打开，看到的都还是
`**粗**` 与 `<span …>`。

### 2.3 为什么这次敢重新引入 `OffsetMapping`

ADR-021 下线加粗的理由是「隐藏字符必须配真实的偏移映射，第一版就崩过、
后来又光标跳位」。这个理由**没有消失**，但可以正面处理：

| ADR-021 的顾虑 | 本文的处理 |
| --- | --- |
| 渲染文本比源文本短，映射长度不一致会崩 | 映射是**按源长度 + 1 与渲染长度 + 1 各建一张表**，两端都 clamp，越界不抛异常 |
| 光标跳位（映射边界错） | 隐藏字符映射到它被移除处的输出位置；边界单独写了单测（`MarkdownInlineRenderingTest`） |
| 映射只服务一种样式，维护成本高 | 现在服务两种（加粗、颜色），同一套递归 walk，成本被摊薄 |
| 流式/半截标记（`**你` 未闭合） | **未闭合按开启处理**：标记样式化到文本块末尾，输入过程始终是活的 |

`EditorRendering`（当年被删掉的那份）的做法被保留下来：一个源偏移一张表、
一个渲染字符一张表。区别是本文的隐藏集合包含颜色，且未闭合标记不再
按「不匹配」处理而是按「仍开启」处理——这是为了让粘滞模式在打字过程中有实时反馈。

### 2.4 空 run 不留下垃圾字符

开关模式下最容易积攒的垃圾是 `****` 与空的 `<span></span>`。`MarkdownInlineEditing.close`
按三个分支处理：

1. **开与关之间没打字** → 把开标记**撤掉**，文本回到原样；
2. 关标记已经紧挨光标 → 什么也不做；
3. 否则在光标处补上关标记。

以及一条保护：光标不在本格式的 run 内时，**什么都不写**。随手点一下关闭按钮
不该在段落中间凭空插进一个 `**`。

### 2.5 `**` 既是开也是关，必须向前配对

`MarkdownInlineEditing.unmatchedOpener` 对 `**` **正向扫描**、成对翻转：
遇到开标记则记下、遇到下一个则视为配对完成。反向搜索会把**已完成的** run 的
闭标记误认成新 run 的开标记，导致「打一段字再关加粗」时补上第三个 `**`。
`<span>`/`</span>` 标记不同，用栈配对，取最内层未闭合的那一个。

## 三、兼容

- **数据格式零变更**，与 ADR-048 写入的完全一致；
- 旧记录的 `**…**`、`<span …>` 打开就是粗体/彩色，不再显示标记；
- 行内图片引用、链接、`*斜*` 等**不隐藏**：它们需要被看见、被编辑、被删除；
- 旧版 app 打开新记录：标记仍在文件里，按字面显示，功能不丢。

## 四、已知限制

1. **隐藏发生在整个文本块内**，因此「块内出现未闭合 `<span>`」会让后续文字
   一直着色到块尾。这是粘滞模式的实时预览代价，关闭格式即补上闭合标记。
2. **格式模式不能跨块**：换到另一个文本块（中间隔着图片块）时，
   新块不会自动接续上一块的格式。切块时模式保持开启，但 Markdown 的 run
   是块内语义，跨块强行延续会产生嵌套。
3. **斜体仍只有数据支持**，没有按钮（ADR-048 的结论不变：中文无真斜体字形）。
4. **没有 undo**：点错了要自己删标记。
5. **未在本机编译**（AGENTS §1 禁止本机 Gradle），验收以 CI 为准；
   映射边界、开关语义、半截标记都有 JVM 单测兜住。

## 五、R1 模块准入四问

1. **模块归属**：全部在既有 `:feature-editor`，不新增模块。
2. **依赖方向**：无新增依赖边。`MarkdownInlineEditing` 是纯 Kotlin，
   连 `:core-storage` 都不依赖；`MarkdownInlineRendering` 只用 Compose 文本 API。
3. **对外接口**：`EditorToolbar` 新增 `activeFormat: InlineFormat?`，
   **带默认值 `null`**，既有调用点不受影响；`EditorModule` 冻结签名未改。
4. **数据格式**：无变更。
