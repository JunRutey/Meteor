# ADR-069 · 每日一问界面重做：浏览 / 提问 / 回答三段式，时间选择统一为滚轮

> 状态：已采纳。关联：[ADR-068](ADR-068-daily-question-replaces-save-memory.md)（每日一问的数据与提醒）、
> [ADR-060](ADR-060-merged-bottom-quick-entries.md)（底部快捷入口）。
>
> 本 ADR 只改界面与交互；存储、加密、闹钟、通知与跳转链路一个字节未动。

## 一、问题

ADR-068 把功能做出来了，但把三件事塞进了两屏：

1. **列表页第一项是提问表单**。一个 3–6 行的输入框、提醒区、保存按钮固定在最上面，
   已提问题被挤到下面；打开列表想回看旧问题，要先滑过一张表单。
2. **详情页把提醒、编辑器、回答堆在同一列**。未回答的问题进入就是编辑器，编辑区上方
   还有提醒区与两个全宽「加提醒」按钮；已回答的问题要滚到所有回答之后才能「再回答」。
3. **列表卡片信息过载**。状态、回答数、回答预览、最后回答时间、下次提醒、创建时间、
   常驻的删除 × 挤在一张卡里，没有主次；删除 × 又紧挨正文，容易误触。
4. **时间选择与应用里唯一的另一处日期选择不一致**：生辰页是「三列滚轮 + 点一下选中」，
   每日一问用的是系统 `DatePickerDialog` / `TimePickerDialog`。
5. 回答编辑器的工具栏里有链接与图片两个按钮，但宿主传的是空实现：链接对话框确认后
   什么也不会发生，图片按钮按了没有反应。

功能本身（多提醒、多回答、默认明天同一时刻、通知跳转、删除）没有问题，问题在布局与
操作路径。

## 二、决定

### 二.1 列表只负责浏览

- 打开列表看到的是页头（返回 / 标题 / ＋）、三个筛选胶囊（全部 / 待回答 / 已回答，
  各带数量）与卡片列表。提问搬去独立页面。
- 卡片只保留四层信息：状态胶囊 + 一条状态行（下次提醒或回答次数）、问题正文（最多
  三行）、最近一条回答预览（已答时，弱化）、提问时间。
- 删除收进卡片右上角的「⋯」菜单，不再常驻 ×。
- 没有任何问题时，空态卡片里直接给「写下一个问题」按钮。

### 二.2 提问是独立页面

- 新路由 `questions/new`，新页面 `QuestionComposeScreen`。
- 正文输入框占据主要区域；提醒放在下方卡片里，chips 横向排列，最多 8 条也只占一行。
- 默认提醒仍是「明天同一时刻」，以一条可删除的 chip 出现；只写正文直接保存也成立。
- 底部固定「保存问题」，与日记编辑页的保存按钮同尺寸（52dp 胶囊）。

### 二.3 详情分成阅读与回答两种形态

- **阅读**：问题卡 → 提醒 chips → 回答列表（按时间正序）；「回答 / 再回答一次」固定
  钉在底部，永远不用滚到列表末尾去找。删除在页头「⋯」里。
- **回答**：整屏是编辑器。问题缩成上方一张引用卡，页头变成「取消 / 标题 / 预览」，
  底部是 52dp 的「保存回答」。
- 修改 ADR-068 的中心规则：**详情永远先阅读**，点底部「回答 / 再回答一次」才进编辑。
  未回答的问题不再被自动弹进编辑器；从列表、从通知点进来看到的是同一个页面，先看清
  问题与已有回答，再决定要不要写。
- 编辑模式里返回 = 退回阅读（有未保存草稿先确认），不会静默丢字；系统返回键走同一条
  路径。
- 保存回答后自动滚到最新一条。

### 二.4 时间选择统一为生辰页同款滚轮

- 新增 `QuestionWheelPicker`：年 / 月 / 日 / 时 / 分五列，144dp 视口、36dp 行高、
  2dp 行距、选中行 `primaryContainer` 圆角、`surfaceContainerLow` 面板、18dp 圆角，
  数值与生辰页 `BirthDatePicker` 完全一致。
- 交互也一致：拖动只预览，**点某一行才选中**；面板里给「取消 / 确定」，早于现在的
  时刻直接判非法并禁用确定。
- 为什么是一排五列：提醒需要日期与时间一起看，分两屏会多一次「下一步」；五列在
  360dp 屏幕上用权重分配宽度仍然可读。
- 为什么代码是镜像而不是复用：生辰选择器在 `:app`，每日一问在 `:feature-question`；
  R1 不允许 feature 反向依赖 app。抽公共控件需要一个新模块，这是比本次界面重做更大的
  架构决定。若出现第三处滚轮选择，应新建 `core-ui` 模块并把生辰页一并迁过去。

### 二.5 ViewModel 与编辑器的配套调整

- 新增 `QuestionComposeViewModel`，把草稿、提醒增删与保存从
  `QuestionListViewModel` 拆出来；列表 VM 只剩读取与删除。
- `QuestionDetailViewModel` 增加 `cancelAnswer()` 与 `insertLink()`。
- 回答编辑器的链接按钮接上 `MarkdownEditing.appendLink`（与日记同一条插入路径）；
  图片入口暂时隐藏（`MarkdownField(showImageAction = false)`），因为回答还没有媒体
  导入链路，留一个按了没反应的按钮比暂时没有按钮更糟。

## 三、R1 四问

1. **属于哪个模块？** 界面在 `:feature-question`（新增 `QuestionComposeScreen`、
   `QuestionChrome`、`QuestionReminderEditor`、`QuestionWheelPicker`）；视图模型与
   导航接线在 `:app`。不新增模块。
2. **依赖谁？谁依赖它？是否单向、是否成环？** 模块依赖边没有变化：仍然是
   `feature-question → feature-editor`，`:app → feature-question`。新增的
   `androidx.activity:activity-compose` 是库依赖（`BackHandler`），不是模块边；版本仍
   由 `gradle/libs.versions.toml` 统一。
3. **对外接口是什么？是否足够窄？** `feature-question` 新增
   `QuestionComposeScreen` 一个 Composable；三个页面仍只收**已格式化**的数据模型与
   回调，不导航、不读 DI、不持久化。`QuestionReminderEditor` / `QuestionWheelPicker`
   保持 internal。`MarkdownField` / `EditorToolbar` 只新增带默认值的 `showImageAction`
   参数，所有既有调用点行为不变。
4. **数据格式变更？是否向后兼容？** 无。`每日一问/<id>.bin` 的 JSON、`ReminderPick`
   的字段、提醒调度策略、通知渠道与 `QuestionOpenRequest` 全部不变；旧版本写下的问题
   与回答照常打开。

## 四、后果

- 打开列表不再先看到表单；提问多一次页面跳转（＋或空态按钮），换来列表可读性。
- 从通知点进来不再直接进编辑器，而是先看到问题与「回答」按钮；多一次点击，换来列表、
  通知、历史记录三种入口行为一致。
- 时间选择从系统对话框换成滚轮，第一次打开会看到「明天同一时刻」已预选；点「确定」
  即接受默认值。
- 滚轮代码在 `:app` 与 `:feature-question` 各有一份，视觉与交互一致但实现镜像；
  第三处出现时应抽模块（见二.4）。
- 回答编辑器暂时不能插图（按钮已隐藏）；链接可以插入。插图需要把媒体选择与导入
  接到回答页，属于后续独立改动。
- 列表的「待回答 / 已回答」按**有没有回答过**划分；已回答但又被加了提醒的问题仍会
  显示下次提醒。

## 五、不变量

- 没有服务端；问题与回答仍只在本机。
- 存储格式、加密密钥、原子写入、备份兼容性不变。
- 提醒仍受通知总开关约束；闹钟仍按问题最早一条待提醒调度，通知按钮行为不变。
- 问题与回答不进搜索索引，也不成为 AI 的档案证据。
- 面向用户的文案全部走 `strings.xml`。
