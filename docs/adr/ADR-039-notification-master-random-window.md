# ADR-039 · 通知总开关与每日 8:00–9:00 随机提醒

- 状态：已接受
- 日期：2026-11-20
- 关联：ADR-033（每日提醒与通知渠道）、ADR-013（设置持久化）、ADR-040（备份覆盖设置）

## 背景

ADR-033 把通知做成了若干细分项：每日写日记提醒开关、提醒时间选择器、精确闹钟说明与
通知渠道提示。实际使用中这些细分项让设置页显得复杂，而“更新下载进度”与“每日提醒”
本来就是同一类用户意图——是否允许 Meteor 发通知。

v1.3.0 起通知区收敛为一个总开关，同时控制两类通知：

1. 应用内更新下载/下载完成通知；
2. 每天 8:00–9:00 之间随机一个时刻的写日记提醒。

每日提醒不再判断“今天是否已经写过日记”。需求是每天一条，而不是“缺日记才提醒”。

## 决定

### 设置层

- `AppSettings` 新增 `notificationsEnabled`，默认 `true`；移除
  `diaryReminderEnabled` 与 `diaryReminderTimeMinutes`。
- 设置页通知区只保留一个开关，文案标题为“允许通知”，副标题说明它同时覆盖更新下载与
  每日提醒。删除时间选择器。
- 保留系统通知权限与精确闹钟的“不可用”提示和跳转入口，但它们不是可配置细分项：
  - 系统通知权限/日记提醒渠道不可用时，提示并提供“打开通知设置”；
  - Android 12+ 精确闹钟未授权时，提示会以非精确方式触发，并提供授权入口。
- 首次启动引导页文案同步改为：通知总开关默认开启，包含更新下载进度与每日
  8:00–9:00 随机写日记提醒，可跳过系统权限并随时在设置中关闭。
- 旧键 `diary_reminder_enabled` 只作为迁移来源保留，不再写入；旧键
  `diary_reminder_time_minutes` 不再读写。UI 不再出现任何提醒时间。

### 默认值与迁移

新增主键 `notifications_enabled`，读取时按以下优先级取值：

1. 若 `notifications_enabled` 已存在，使用它；
2. 否则若旧键 `diary_reminder_enabled` 存在，沿用旧值；
3. 否则为 `true`。

`SettingsRepository.migrateNotificationsMasterSwitch()` 在应用启动时把结果一次性写入新键，
之后旧键不再影响行为。

选择理由：

- 旧版默认“下载通知一直有”，新总开关默认 `true` 保持这一体验；旧安装若从未动过提醒
  开关（没有旧键），升级后下载通知仍会出现。
- 旧键存在说明用户显式做过选择。总开关是旧提醒开关的超集，沿用旧值能保证升级不会把
  用户明确关闭的提醒重新打开；代价是这类用户的下载通知也会一起关闭，用户重新打开总开关
  即可恢复两类通知。该取舍在发布说明中说明。

### 每日随机窗口

`core-notify` 的 `DailyReminderPolicy` 改为纯函数策略，随机源以 `(Int) -> Int` 注入，
参数是上界（返回 `0 until bound`），便于单测：

- 当前时间在 8:00 前且今天未发：在 08:00–08:59 中随机一个整分钟；
- 当前时间在 08:00–09:00 且今天未发：在“当前时刻之后的第一个整分钟”到 08:59 之间随机，
  若剩余不足一分钟则定在 09:00；
- 当前时间在 09:00 及以后，或今天已发：排到明天的 8:00–08:59 窗口。

`DailyReminderScheduler` 从“按小时/分钟排下一次”改为 `scheduleAt(ZonedDateTime)`，
仍然优先 `setExactAndAllowWhileIdle`，未授权时回退 `setAndAllowWhileIdle`。

### 同一天不重复

- `SettingsRepository` 增加内部键 `reminder_last_sent_local_date`（ISO 本地日期），
  提供读取/写入方法。
- 发送成功后写入当天日期；调度和闹钟触发时都先比较该日期。
- 今天已发过则下一次直接排到明天窗口，重启、升级或重复广播都不会再发第二条。
- 该内部键不进入设置快照（ADR-040）：换机恢复后应重新按新设备的当天窗口调度。

### 通知文案与 x

- 标题：“你写日记了吗？”
- 正文：“距今天结束还有 %1$d 小时，时间正沿着星河向前，愿你记录下美好。”
- 正文通过 `BigTextStyle` 完整展开。
- `x = 发送时刻到当天 24:00 的整小时数（向下取整）`：
  - 08:00 → 16，08:30 → 15，08:59 → 15，09:00 → 15。
  - 允许 ±1 小时误差；向下取整与需求示例（08:30 → 15）一致。
  - 用本地时区计算，避免夏令时/时区切换后出现负数。

### 更新下载通知

- `AndroidNotificationFeature.showUpdateDownload/showUpdateReady` 在总开关关闭时不 post，
  并取消已有更新通知。
- 这两个方法是非 suspend，可能运行在下载协程中；实现用设置流的缓存值判断总开关，
  不阻塞主线程，也不在通知方法里同步读 DataStore。
- 总开关关闭时 `syncReminder()` 同时取消闹钟与更新通知。

### 模块与 R1 四问

1. **模块归属：** 随机窗口策略仍在 `:core-notify`；偏好键、迁移与设置页在
   `:feature-settings`；通知展示、权限与调度组装在 `:app`。
2. **依赖方向：** 不新增模块，不新增依赖边。仍是 `app → core-notify`、
   `app → feature-settings`，`core-notify` 保持纯 Kotlin/Android 平台逻辑，不依赖设置或存储。
3. **对外接口：** `DailyReminderPolicy` 只暴露下一次触发时间与“距当天结束小时数”；
   `SettingsRepository` 只增加总开关、最后发送日期和批量快照方法；`NotificationFeature`
   仍保持窄接口（未修改冻结接口）。
4. **数据格式：** DataStore 新增两个键并保留旧键作迁移来源；不修改档案文件格式。
   旧安装升级不丢选择，新安装默认开启通知。

## 后果

- 设置页更简单，通知只受一个开关控制；用户若只想关闭每日提醒，需要连同下载通知一起
  关闭——这是“总开关”的直接后果，发布说明需写明。
- 提醒时间不再可配置，固定为 8:00–9:00 随机，降低“每天同一分钟”的可预期性。
- 每日提醒与是否写日记解耦，已写日记的当天仍会收到一条提醒。
- 非精确闹钟设备上提醒可能晚于 9:00；设置页在未授权精确闹钟时给出提示与入口。
- 旧提醒时间键被忽略，不回填、不迁移到新语义。
