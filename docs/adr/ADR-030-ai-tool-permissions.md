# ADR-030 · AI 工具权限细分、只读工具扩容与调用规范化

- 状态：已接受（v0.7.5）
- 日期：2026-11-06
- 关联：ADR-027（联网 AI、隐私边界）、ADR-028（读写分级与不可逆操作）

## 背景

ADR-028 把 AI 能力分成「读 / 写 / 不可逆」三类，但写权限只有一个总开关：
打开后模型同时拥有「写日记与心情」和「新建/更新人物」两组工具。用户提出两点：

1. 想要更细的权限控制，能只放开其中一组；
2. 想要更多「底层」工具，同时要求调用被规范化、隔离与限制。

## 决定

### 1. 能力登记表取代隐式约定

新增 `AiToolCapability { READ_ARCHIVE, WRITE_DIARY, WRITE_PEOPLE }` 与
`AiToolPermissions`。`ArchiveTools` 里维护**唯一**的 `TOOL_CAPABILITIES` 表：

- `specs()` 只返回「已登记 + 已授予 + 依赖可用」的工具；
- `execute()` 先查表：未登记 → `unknown-tool`，未授予 → `permission-denied`，
  参数不合法 → 具体错误码；全部在真正触碰存储之前完成。

新增工具必须同时给出能力项，否则永远不会被暴露。这样「默认拒绝」不再依赖
每个工具函数里重复写 `if (!writeEnabled)`。

### 2. 写权限拆成两组，主开关仍保留

- 主开关 `aiWriteEnabled` 不变（默认关闭，显式同意）；
- 新增 `aiWriteDiary`、`aiWritePeople`，**默认 true**：升级后行为与 v0.7.4 完全一致；
- 实际授予 = 主开关 && 细分开关（`AiConfig.toolPermissions`），任何一边关闭都收回。

### 3. 只读工具扩容（11 个）

新增三个只读工具，全部不返回二进制：

- `archive_overview()`：记录/日记/人物计数与日记日期范围，正文一律不返回；
- `list_attachments(person_id?)`：附件元数据（文件名、类型、大小、日期、归属）；
- `read_attachment_text(attachment_id)`：仅返回导入时抽取的文本（上限 4000 字）。

附件工具依赖 `AttachmentStore`；没有注入该依赖时不出现也不可执行。

### 4. 调用规范化与隔离

- **严格参数类型**：字符串参数必须是 JSON string，数字/对象/数组/`null` 一律按缺省处理，
  不再被 `optString` 强转成 `toString()`，避免构造出奇怪路径或 id；
- **长度上限**：所有字符串参数（200 字）、写入正文（20000 字）、附件文本（4000 字）都有上限；
- **人员作用域**：`allowedPersonId` 同时约束记录、检索、附件与写工具；
- **结果上限**：`AiAgent` 仍按 2500 字/调用、24000 字/轮封顶，`archive_overview` 等工具本身也只返回计数；
- **逐次写入确认**：写工具执行前必须由应用界面展示完整参数并取得用户明确确认；拒绝、关闭或没有确认界面时一律不执行。附件抽取文本视为不可信输入，不能绕过该确认边界；
- **不开放**：删除、导出、导入、改 Key、开关应用锁、任意文件/网络/Shell 能力。

## 后果

- 用户可以把「读日记」与「改人物」分开授权，prompt injection 的影响面更小；
- 即使启用了写权限，模型也不能自行完成写入；每次具体变更都需用户在本机确认；
- 工具清单与能力表在代码中一一对应，新增工具时漏登记会直接不生效（fail closed）；
- 默认值保证旧安装升级后工具面不变，不需要数据迁移；
- 未来新增工具时，仍需更新本 ADR 与 README 的工具数量（ADR-028 的约束继续有效）。
