# ADR-071 · 首页侧边栏：点「Meteor」打开的功能总入口

> 状态：已采纳。关联：[ADR-060](ADR-060-merged-bottom-quick-entries.md)（底部快捷入口）、
> [ADR-070](ADR-070-daily-question-asked-on.md)（每日一问按天归档后，总览需要一个新家）。
>
> 本 ADR 只加一层导航抽屉；首页现有快捷卡片、AI 悬浮按钮与页头搜索 / 设置图标全部保留。

## 一、问题

应用的功能已经从「日历 + 日记」长到了相册、人际关系、AI、搜索、设置、每日一问。
这些入口目前散在三处：

- 页头：搜索、设置；
- 日卡片上方的快捷卡片：相册、人际关系；
- 右下角悬浮按钮：AI 对话；
- 新增的「每日一问」总览（ADR-070 之后不再占日卡片入口）。

功能一多，首页就开始承担「导航中心」的职责，但它本身是一个日历。需要一层不占首页
面积的入口：从页头标题展开一个侧边栏，把功能集中放进去。用户明确要求：

- **点顶部「Meteor」** 打开；
- 侧边栏放这些功能；
- 每日一问的**总览**放进侧边栏；
- 首页现有的快捷入口**保留**，侧边栏做补充，不做替换。

## 二、决定

### 二.1 触发与位置

- `CalendarHeader` 的标题「Meteor」变成可点区域（右侧加一个 16dp 向下小箭头），
  点击打开左侧抽屉；只有宿主传入 `onOpenDrawer` 时才可点，嵌入式日历仍然是无动作标题。
- 抽屉由 `HomeTabsScreen` 托管：它是首页两 tab 的唯一外壳，侧边栏因此同时覆盖
  生辰与日记两个 tab，并盖住底部 tab bar。
- 关闭方式：点遮罩、点右上角 ×、系统返回键。

### 二.2 内容

抽屉从上到下：

1. 「Meteor」标题 + tagline「记录 · 回看 · 被提醒」+ 关闭 ×；
2. 分组标题「功能」；
3. 每日一问（总览）—— `QuestionListScreen`；
4. 相册 —— `album`；
5. 人际关系 —— `people`；
6. AI 对话 —— 只在 `aiEnabled` 时出现；
7. 搜索 —— `search`；
8. 分隔线后：设置 —— `settings`；
9. 底部：`Meteor v<versionName>`。

每一项是 40dp 浅色图标方块 + 标题 + 一行说明，点击后先关闭抽屉再导航。

### 二.3 视觉与动效

- 面板宽 300dp、占满内容高度、右侧 24dp 圆角、`surface` 底色、12dp 投影。
- 遮罩用 `colorScheme.scrim` 32% 不透明度，只淡入淡出；面板从左侧滑入，
  时长与缓动走 `MotionTokens.enter()/exit()`。
- 关掉动效（设置里的总开关）时，两者直接出现 / 消失。
- 图标全部用 `Canvas` 画（问号气泡、相册、人物、星芒、放大镜、滑杆、×），
  不引入 `material-icons`。

### 二.4 为什么不替换首页快捷入口

用户明确选择「保留首页快捷入口，侧边栏只做补充」。所以：

- 日卡片上方的「相册 / 人际关系」快捷卡片保留；
- AI 悬浮按钮保留；
- 页头右上角的搜索 / 设置图标保留。

侧边栏是**功能总入口**，不是唯一的入口。这样首页保持原有节奏，侧边栏承担
「功能变多以后的一览与兜底」。重复是有意的：常用动作仍然一步可达，不常用的
从抽屉里找。

### 二.5 为什么不做 Material3 的 ModalNavigationDrawer

- 项目里没有任何 `material3` 抽屉用法；自定义面板可以沿用首页的圆角、阴影和
  浅色图标方块，不需要为抽屉单独引入一套 `DrawerState` / `DrawerValue` 语义。
- 现有全局动效开关（`animationsEnabled`）需要同时控制遮罩与面板；自己写两条
  `AnimatedVisibility` 比包一层实验性 / 约定不同的 API 更直接。
- 抽屉只需要「开 / 关 + 几个回调」，自绘 200 行比引入一整套 drawer 组件更窄。

## 三、R1 四问

1. **属于哪个模块？** 纯 `:app`：`ui/home/HomeTabsScreen.kt`（托管与动画）、
   `ui/home/HomeDrawer.kt`（面板与图标）、`ui/MeteorNavHost.kt`（回调接线）、
   `feature-calendar` 的 `CalendarHeader` 只加一个可空的 `onOpenDrawer` 参数。
   不新增模块。
2. **依赖谁？谁依赖它？是否单向、是否成环？** 没有新增模块边。`:app` 已经依赖
   `:feature-calendar` 与 `:feature-question`（取标题 / 快捷入口文案与 R），
   侧边栏只是使用现有的依赖。
3. **对外接口是什么？是否足够窄？** `HomeTabsScreen` 新增 6 个导航回调、`versionName`
   与 `animationsEnabled`；`HomeDrawer` 是 `:app` 内部的 Composable，全是数据与回调；
   `CalendarHeader` 新增一个带默认值的可空参数。没有存储、DI 或路由类型泄漏进面板。
4. **数据格式变更？是否向后兼容？** 无。抽屉不碰任何档案、偏好或路由参数；
   版本号只用于显示。

## 四、后果

- 首页标题第一次成为可点元素；没有动效时抽屉直接出现，不会闪。
- 抽屉状态用 `rememberSaveable` 保存，配置变更后不会莫名消失；进程重建后可能重新
  出现为打开，这是可接受的。
- 抽屉里的入口与首页快捷入口重复，这是用户明确选择的结果；如果将来要收掉快捷
  入口，删的是 `CalendarScreen` 的 `QuickActions`，与抽屉无关。
- 侧边栏只在首页出现；进入任何一个功能页后，回首页才能再打开。这避免了在二级页面
  里再叠一层全局导航。
- 面板宽 300dp 在 320dp 宽的设备上只剩 20dp 遮罩，仍可点；极窄屏下文字说明会省略。
