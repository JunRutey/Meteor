# ADR-019 · 编辑器收敛为「加粗 + 图片 + 链接」，颜色与斜体下线

- 状态：已接受（v0.4）
- 影响：`:feature-editor`
- 取代：[ADR-018](ADR-018-drop-wysiwyg-rich-text.md) 中「不做所见即所得」的结论

## 背景

v0.4 的编辑器先做到了四件事：加粗、斜体、三种颜色、图片/链接。实际用下来，
后两者的问题比收益大：

1. **颜色表达不了多少信息，代价却不小。** 只有三个色点，而 Markdown 没有颜色语法，
   只能写 `<span style="color:#RRGGBB">`。这段标记在导出备份、在其他 Markdown 工具、
   在将来的 AI 读取里都是噪音；为了让它在编辑区不可见，还要为它单独维护一段
   光标映射。
2. **中文没有真正的斜体。** 系统是把字形倾斜合成，观感差、可读性下降，
   而且中文写作里「斜体」本来就没有稳定的语义（强调靠加粗、引号、书名号）。
3. **每多一种隐藏标记，`EditorRendering` 的偏移映射就多一条分支。** 那正是最容易
   出错的地方（标记隐藏第一版就因为长度不一致直接崩溃过）。

## 决策

编辑区只保留 **加粗**（`**…**`）、**图片**、**链接**：

- 工具栏：`B`、链接、图片、预览 —— 一行放得下，不再需要两行。
- `EditorRendering` 只隐藏 `**`；图片与链接本来就是内容，必须可见可改。
- `MarkdownEditing` 删除 `toggleItalic` / `toggleColor`，不再产生这两种标记。
- `MarkdownStyles` 退化为**仅供预览**的解析器，并新增 `kinds` 参数，
  让编辑区只关心加粗。

## 兼容：老记录不迁移

已经写下的 `<span …>` 与 `*斜体*` **不做数据迁移**：

- 预览继续渲染它们（`MarkdownStyles` 保留对应分支），旧日记的观感不变；
- 编辑区把它们**按原文显示**。这是刻意的：如果继续隐藏，用户就再也删不掉
  一个已经不再支持的样式——那才是真的把数据锁死。

代价是老记录里若真有颜色/斜体，编辑区会看到裸露的标记，手动删掉即可。

## 后果

- 新增样式只有一种走「隐藏标记」的路径，偏移映射的实现与测试都只剩一条主线。
- `MarkdownStyles` 的「长度不变」不变量不再需要——预览本来就不映射光标，
  编辑区的长度不变量由 `EditorRendering` 独自负责。
- 若将来重新需要颜色，正确的做法是**在预览里支持**、不在编辑区支持，
  这样不引入新的光标映射分支。
