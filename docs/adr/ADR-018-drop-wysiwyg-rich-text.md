# ADR-018 · 不再实现所见即所得富文本，Markdown 方案定稿

- 状态：**部分作废**（结论已被 [ADR-019](ADR-019-editor-keeps-bold-images-links.md) 取代）
- 影响：`:feature-editor`

> 保留本文作为决策轨迹。两点已被推翻：
> 1. 编辑区**已经**实现所见即所得——加粗标记被隐藏、文字直接显示为粗体
>    （`EditorRendering`，带真实光标映射）；
> 2. 加粗/斜体按钮**已经**存在过，最终只保留了加粗（ADR-019）。
>
> 仍然成立的部分：数据始终是 Markdown（文件是真相源），`EditorModule` 冻结接口不变。

## 背景

v0.4 的目标是「富文本编辑器」。实现过程中先后评估了三条路线：

1. **`richeditor-compose`**：Maven Central 最新为 `1.0.0-rc13`（2025-06），
   仍是 RC，且 Composable 入口在 rc 之间变动过。本仓库本地禁止构建、shell 无外网，
   无法验证其 API 签名，接入失败的成本是一轮 CI 往返。
2. **自研块编辑器**：把正文拆成段落/标题/图片/列表块。可控但工作量大，
   且会脱离 Markdown——而 Markdown 正是导出备份可读、索引可搜、AI 可读的前提。
3. **Markdown 编辑 + 只读预览**：编辑区是纯文本，预览区渲染排版与图片。

## 决策

**采用第 3 条并定稿，不再追求所见即所得。**

理由：

- 数据仍是 Markdown，符合档案 §5.1（文件是真相源）与 R4；
- 导出、索引、将来的 AI 读取都直接受益，不需要为富文本另存一份结构；
- 已覆盖实际使用中最主要的诉求：插图片、插链接、看排版。

## 已完成的范围

- `EditorModule` 冻结接口（open / save / render / insertImage / insertLink）
- 图片：压缩（最大边 1568、JPEG 80）→ AES-GCM 加密 → 随机文件名落盘 →
  正文写入 `![](meteor://image/<token>)`
- 链接：对话框输入地址与显示文字
- 预览：一级~三级标题、无序列表、分隔线、加粗、斜体、链接下划线、**内联图片**
- 独立图片库（`:feature-gallery`）可单独浏览全部加密图片

## 明确不做的部分

- 编辑区内直接看到排版（所见即所得）
- 选区加粗/斜体按钮
- 编辑区内的内联图片
- 表格、代码块高亮、任务列表
- 图片缩放与图注

## 后果

- 路线图上 v0.4 结项，不再有其他编辑器工作。
- 若将来确需所见即所得，`EditorModule` 的冻结接口不变，替换实现即可——
  这正是当初把接口冻结、把实现藏在 `MarkdownEditorModule` 里的原因。
