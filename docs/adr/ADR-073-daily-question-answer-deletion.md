# ADR-073 · 每日一问允许删除单条回答

> 状态：已采纳。关联：[ADR-068](ADR-068-daily-question-replaces-save-memory.md)（每日一问）。

## 一、问题

ADR-068 把回答定义为 append-only：写错的回答只能留在档案里，没有纠正路径。这在
「每次回答是一个时间点」的语义下是合理的，但忽略了一个真实场景——用户写错了、
写重了，或某条回答不再代表自己的想法，却无法撤回。

「不可编辑」与「不可删除」是两件事。保留前者（回答仍是 append-only 的**写入**模型，
旧回答不被覆盖）就能保住时间点语义；开放后者只是给误写一条纠错路径。

## 二、决定

- `QuestionStore` 新增 `deleteAnswer(id, answerId)`：按 answer id 精确移除一条，
  返回更新后的 `StoredQuestion`；问题或回答不存在时返回 `null`（no-op）。
  该方法是**带默认实现**的新增方法，没有改动任何既有签名。
- 写入语义不变：回答仍只能追加，删除是唯一的移除方式，且不可恢复。
- **不自动恢复提醒**：删掉最后一条后问题回到「未回答」，但待提醒集合原样保留。
  删除是纠错，不是「再提醒我」的请求；想要提醒的用户可以手动加。
- UI：每条回答卡带一个「删除这条回答」入口，点开先确认再删除；写盘失败原地报错，
  不把用户送走。删除进行中禁用其它写操作。

## 三、R1 四问

1. **属于哪个模块？** 存储语义在 `core-storage`（`QuestionStore`）；展示与确认在
   `feature-question`；写盘调度与错误文案在 `:app` 的 `QuestionDetailViewModel`。
   都是既有模块内部扩展，不新增模块。
2. **依赖谁？是否成环？** 不引入任何新依赖边。`feature-question` 仍只收已格式化的
   展示模型，`deleteAnswer` 意图由 ViewModel 发、`feature-question` 不认识存储。
3. **对外接口是否够窄？** `deleteAnswer` 只收发 `id`/`answerId` 与更新后的记录，
   与 `addAnswer`/`updateReminders` 同级。
4. **数据格式变更？是否向后兼容？** **无格式变更**：仍写同一个 `version:1` 的
   JSON，只是 `answers` 数组少一项。旧客户端读到的是「少了一条回答」的合法文件。
   冻结接口（§8）一个字符未动。

## 四、后果

- 回答不再是绝对不可变的历史；但因为没有「编辑」，时间点语义仍成立——改主意的表现
  是「删掉旧的、写一条新的」，新回答带新的时间戳。
- 删除不可恢复，也没有回收站；与删除整个问题、删除日记的取舍一致。
- 备份、索引、AI 工具若将来消费回答，需处理「回答数减少」这一增量事件（本 ADR
  不涉及那些通道）。

## 五、不变量

- 没有服务端；删除只在本机生效。
- 正文静态加密、密钥绑定设备不变。
- 面向用户的文案全部走 `strings.xml`（`feature/question` 与 `:app`）。
