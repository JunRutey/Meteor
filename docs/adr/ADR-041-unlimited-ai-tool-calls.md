# ADR-041 · AI 工具调用不再设次数上限

- 状态：已接受
- 影响：`:feature-ai`（`AiAgent` 工具循环）、`:app`（错误文案映射）

## 一、问题

`AiAgent` 原先有三道硬预算：

- 一次对话最多 6 步（`maxSteps`），用完抛 `AiProviderException("step-limit")`；
- 每一步最多执行模型返回的前 4 个工具调用（`maxToolCallsPerStep`），超出的调用被直接丢弃；
- 所有工具结果累计最多 24000 字符（`maxTotalToolChars`），超出后插入一段
  “工具预算已用完”的提示，让模型停止调用工具。

这三个数字是 v0.7 为防失控临时定下的，与模型能力、档案规模或用户意图都没有关系。
实际使用中，一个需要先列人物、再逐个读档案、最后交叉核对的问题，很容易超过 6 步；
模型一次返回 5 个以上并行查询时，多出来的调用还会被静默丢掉，模型只看到残缺结果，
只能重复查询。用户看到的是“问得稍微复杂一点就失败”，而不是一个明确的能力边界。

## 二、决定

移除工具循环里的**所有调用次数与轮数预算**：

- 删除 `maxSteps`、`maxToolCallsPerStep`、`maxTotalToolChars` 三个构造参数；
- 删除 `step-limit` 异常、`TOOL_BUDGET_NOTE` 预算提示，以及 `:app` 中
  `ai_error_step_limit` 的文案映射与资源；
- 循环只在模型返回**不含 toolCalls 的回答**时结束；空回答、`content_filter` 等
  错误处理保持不变；
- `AgentResult.steps` 与 `AgentResult.toolCalls` 继续如实统计，界面上的过程展示、
  累计 token 用量和耗时统计都不变；
- 模型一次返回多少个工具调用，就执行多少个，不再截断。

这不会改变数据格式，也不影响冻结接口：`AiAgent` 不在 `FROZEN INTERFACE` 列表里，
`AiProvider`、`AiModule`、工具协议与工具审批规则均未改动。删除的是内部构造参数，
现有调用方（`MeteorAiModule`）本来就没有传入它们。

## 三、保留单条结果截断

`maxToolResultChars = 2500` 保留。它不是调用次数预算，而是**单条工具结果的大小上限**：

1. 工具结果会作为一条 `tool` 消息进入对话，并在**后续每一轮**被重新发送给模型；
   一条超大结果会持续占用上下文和 token 预算。
2. 模型返回的 JSON 里可能包含整篇日记或长档案。单条不截断时，一次读取就可能
   超过模型上下文窗口，整个请求直接失败。
3. 截断只影响“这一条结果展示多少”，不影响“能调用多少次工具”。模型仍可继续
   调用其他工具或再次查询，只是每次看到的是有界片段。

因此移除次数限制与保留单条结果截断并不矛盾：前者解决“不让模型干完活”，
后者解决“一条结果把上下文撑爆”。

## 四、风险与边界

- **模型可能长时间循环**：现在没有硬性轮数兜底。模型反复调用工具时，会持续产生
  API 请求与 token 费用，直到模型自己给出回答或用户中断。这是接受该 ADR 的主要代价。
- **用户可以中断**：对话页返回、退出应用或系统回收进程时，`AiViewModel` 的
  `viewModelScope` 被取消，正在等待的网络请求与工具循环随协程一起结束。当前界面
  没有独立的“停止生成”按钮，若后续出现大量长循环反馈，应补充显式停止入口，
  而不是重新引入任意轮数上限。
- **没有服务端兜底**：DeepSeek 官方接口不提供应用侧可配置的“最大工具轮数”，
  客户端仍是唯一能决定何时停止的地方；本 ADR 选择把停止权交给用户。
- **工具审批仍按轮生效**：同一模型轮内的写工具共用一次审批决定；没有调用次数
  上限不代表绕过审批。写权限、人物作用域与 `user-denied` 失败关闭逻辑都没有变化。
- **真实故障仍是故障**：空回答、内容审核拒绝、网络错误、工具执行异常照旧抛出，
  不会被无限循环掩盖。

## 五、被否掉的方案

- **把上限调大（例如 30 步 / 20 次调用）**：仍然是任意数字，只是把失败推后；
  不同问题需要的轮数差异很大，最终还会遇到同样的截断。
- **按时间或累计 token 设置预算**：对用户不可解释，而且与“是否已经得到答案”
  无关；在慢网络下可能误杀正常请求。累计用量已经记录在设置中，可供观察。
- **只在客户端做超时**：超时值同样任意，且会打断正在等待模型返回的长请求。
- **保留每次调用上限但自动重试被丢弃的调用**：会改变模型可见的对话结构，
  还可能重复执行写工具，比直接执行全部调用更危险。

## 六、后续

- 若需要成本保护，应优先提供用户可理解的“停止”按钮与用量提示，而不是静默截断。
- 发布说明的「变更」中应写明工具调用不再有步数上限；「已知限制」中应写明
  复杂问题可能持续较久、可退出对话页中断。
- 评测或排查时继续看 `AgentResult.steps` / `toolCalls` 与日志里的 steps、tokens，
  它们没有因为移除上限而失真。
