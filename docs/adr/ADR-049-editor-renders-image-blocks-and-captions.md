# ADR-049 · 编辑区把图片引用显示成图片卡片，并支持图片描述

- 状态：已接受（v1.4.0）
- 影响：`:feature-editor`、`:app`、`:feature-people`
- 依赖：[ADR-021](ADR-021-editor-is-plain-text.md)（编辑区纯文本）、
  [ADR-018](ADR-018-drop-wysiwyg-rich-text.md)（数据是 Markdown）

## 背景

ADR-021 把编辑区定为纯文本之后，插入一张图片的代价变得很直白：用户点「图片」，
输入框里凭空多出一行

```
![](meteor://image/数字遗产/图片/_self/f89223eb-…-59a2.enc)
```

这正是用户在截图里报的问题——**插入图片本该看见图片，却看见一串内部路径**。
它不只是丑：那串路径没有可读信息，还会跟着光标被误删、被复制、被编辑坏。

同时「图片描述」这个需求一直没有落点。ADR-018 把它列进「明确不做」，
但记录一张老照片时，说明「这是谁、哪一年」恰恰是最想要的信息。

## 决策

**编辑区按「块」渲染，整行图片引用变成图片卡片；描述沿用 Markdown 的 alt 文本。**

1. **正文先按行切块**（`MarkdownBlocks`）：
   - 一整行恰好是 `![描述](meteor://image/<token>)` → 图片块；
   - 其余连续行 → 文本块，仍是一个普通 `OutlinedTextField`；
   - `parse` / `serialize` 严格互逆，**打开记录不会改写文件**。
2. **图片块直接画图片**，点一下进图片查看器，右上角 × 删除，
   下方一行是描述（没有描述时显示「添加图片描述」）。
3. **描述就是 alt 文本**：写回仍是 `![毕业那天](meteor://image/…)`，
   不引入新语法、不新增字段，明文备份、索引、AI 读取全部照旧。
4. **只把「整行」抬出输入框，不在字符流里隐藏任何东西。**
   `看图 ![](…) 不错` 这种行内引用保持可见可编辑。

## 为什么这不违反 ADR-021

ADR-021 禁的从来不是「看起来像富文本」，而是**隐藏字符**：一旦有字符被藏起来，
渲染文本就比存储文本短，就必须维护真实的 `OffsetMapping`——那正是当年
Compose 崩溃和光标跳位的原因。

图片卡片绕开了这个类别：被抬走的是**一整行**，输入框里的文本和存储的文本
在每个文本块内依然逐字相等，因此**没有偏移映射，也没有长度不变量的负担**。
删除一张图片走的仍然是「改正文文本」这条老路（`MarkdownEditing.removeImage`）。

结论：ADR-021 的规则照旧——**文本块内部不隐藏任何标记**；支持格式的正确姿势
仍然是「插入语法」而不是「隐藏语法」。

## 兼容

- **数据格式零变更**。老记录里本来就是 `![alt](meteor://image/…)`，
  重新打开会直接变成图片卡片；没有描述的老图片显示「添加图片描述」。
- 非 `meteor://image/` 的图片（例如 `https://…`）**保持纯文本**：
  它没法在这里解密显示，假装成图片只会更糟。
- 行内引用的老记录（图片和文字写在同一行）照旧按文本显示，不做迁移。
- 描述里的 `[` `]` 与换行会被就地替换（`MarkdownEditing.sanitizeCaption`），
  否则会提前截断 alt 文本或把引用劈成两行。

## 后果

- 插入图片从「多一行噪音」变成「多一张卡片」，描述点了就能写。
- 编辑区从「一个大输入框」变成「若干块组成的滚动列」，因此：
  - 焦点报告（`onFocusChanged`）改为「任一文本块持有焦点」，人物编辑页的
    身份卡收缩行为（ADR-046）不受影响；
  - 边框从 `OutlinedTextField` 挪到外层容器，视觉与设计稿保持一致
    （2dp 主题色、20dp 圆角）。
- 图片只在**整行**且目标可解密时才是卡片；行内引用、远程图片、失效令牌
  都会退回文本或占位框，不会静默吞掉内容。
- 图片仍不支持缩放与自由图注位置；描述只能是单段文字。
