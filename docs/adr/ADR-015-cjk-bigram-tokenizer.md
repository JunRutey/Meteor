# ADR-015 · 中文分词用应用层 bigram，不引入 `sqlite3_simple`

- 状态：已接受（v0.2）
- 影响：`:core-index`

## 背景

档案 §9 原定「中文分词器：`sqlite3_simple`（支持中文 + 拼音）」。

`sqlite3_simple` 是 SQLite 原生扩展（`.so`），接入需要：

1. 每个 ABI 一份预编译二进制（arm64-v8a / armeabi-v7a / x86_64）；
2. `System.loadLibrary` + `sqlite3_auto_extension` 注册时序；
3. 二进制来源必须可复现——本仓库本地禁止构建，CI 也拿不到官方预编译产物。

## 决策

在应用层预分词，FTS5 使用内置 `unicode61` 分词器：

- 中文连续段切成 **bigram**（`今天的天气` → `今天 天的 的天 天气`），长度为 1 时保留单字；
- 拉丁字母/数字按词切并转小写；
- **建索引与查询使用同一套分词**，保证对称；
- 查询表达式把 token 逐个加引号后用 `OR` 连接，交给 BM25 排序。

纯 Kotlin，零原生依赖，全 API 级别可用，分词逻辑可单测。

## 后果

- 放弃拼音检索。本项目为纯中文使用环境，拼音不是必需项。
- 单字查询同样可命中（bigram 覆盖不到的首尾单字已单独成 token）。
- 索引体积略大于词级分词（bigram 数量约为字数的两倍），在个人记忆规模（数千条）下可忽略。
- 若将来确需拼音或更优分词，`IndexModule` 的冻结接口不变，替换 `CjkTokenizer` 实现即可，属内部升级。
