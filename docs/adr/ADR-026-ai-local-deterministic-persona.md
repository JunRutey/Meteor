# ADR-026 · AI 与数字人格：本地确定性引擎，不联网、不引入模型 SDK

- 状态：已被 [ADR-027](ADR-027-ai-networked-skills-agent.md) 取代（v0.6 修订）
- 影响：新增 `:feature-ai`；`:app`、`:feature-settings`

> 本记录保留当时的推理与取舍。v0.6 最终改为「可关闭的联网提供商 + 技能驱动」，
> 见 ADR-027。本 ADR 的本机检索引擎仍然保留：AI 关闭时作为降级检索，
> AI 开启时作为 Agent 的只读检索工具。

## 背景

档案里 v0.6 的名字是「AI 与数字人格」，`AndroidManifest.xml` 里 v0.1 留下的注释是
「完全离线，直到 v0.6 的 AI」——听上去 v0.6 要联网。但仓库的硬约束与这条路线冲突：

1. AGENTS §7 禁止任何 API key 入库。云模型只能由用户手填密钥，且必须申请 `INTERNET`。
2. README 对用户承诺「密钥绑定设备、不可导出、**不上传、无云端同步**」。一旦把日记正文
   发给第三方模型，这条承诺当场失效。备份已经是明文 zip，是全项目最薄弱的一环，
   不该再开第二个数据出口。
3. 本机禁止构建、shell 只能访问 GitHub，任何模型 SDK（MediaPipe LLM、ONNX、llama.cpp
   绑定）的 API 签名都无法在本地验证；选错一次就是一轮 CI 往返。ADR-017（不引入日历库）、
   ADR-018（放弃富文本库）两次都是同一个教训。
4. CI 只能验证「能否编译」，无法验证联网行为与模型输出。不可验证的能力不适合进发布。

## 决策

v0.6 的 AI 是**在设备上运行的确定性引擎**：不联网、不申请 `INTERNET`、不引入任何模型
SDK，也不保存任何问答历史。

具体三件事：

1. **数字人格**：从某个人物的档案与聊天记录、以及日记里指向 TA 的
   `meteor://person/<person_id>` 链接中，确定性地归纳一份画像——相关记录数、被日记提及
   次数、首末时间、高频词、印象片段。用户可把它**固化**为
   `数字遗产/数字人格/<person_id>/persona.md`（档案 §4 早已定义的位置）。
2. **档案问答**：对问题做应用层分词（CJK bigram + 拉丁词，与 ADR-015 同一套思路），
   用轻量 TF-IDF 在解密后的记录里排序，只返回**命中原文片段 + 日期 + 类型**。
   引擎不生成任何一句话，所以它不可能编造。
3. **引擎可替换**：`AiModule` 冻结，`ask` 是 `suspend`。将来接云端或端侧模型只需替换
   `LocalAiModule`，界面与存储格式不变。

## R1 五问（AGENTS §3）

1. **属于哪个模块？** 新增 `:feature-ai`。人格归纳、检索与界面都在这里；不塞进
   `:core-storage`（那是冻结的存储契约），也不塞进 `:core-index`（见下）。
2. **依赖谁？谁依赖它？** `:feature-ai → :core-storage`（读写记录、人物查询），
   `:app → :feature-ai`。单向、无环，已登记到 `tools/check-module-graph.sh` 的
   `ALLOWED_EDGES` 与 README 的模块图；档案 §3 的图需要同步补这两条边。
3. **对外接口？** 只有 `AiModule` 三个方法（`persona` / `persist` / `ask`）加几个纯数据
   类型；实现、分词、排序、界面全部藏在模块内部。
4. **移除后还能编译、已有数据还能读吗？** 能。删掉 `:feature-ai` 和 `:app` 里的入口即可，
   其他模块不引用它。已固化的 `persona.md` 就是一条普通 `type: persona` 记录
   （`RecordType.PERSONA` 从 v0.1 就存在），备份导出、诊断、列表都照常工作。
5. **数据格式变了吗？** 没有。frontmatter 仍是冻结的五字段；`persona.md` 的正文沿用
   `profile.md` 的「ASCII 头 + `---` + 自由正文」写法。旧版本只会忽略这个文件，
   不需要迁移。

## 为什么不依赖 :core-index

CI 的 `pluggability` 任务会整体排除 `:core-index` 并要求其余模块仍能构建。索引是 FTS
缓存，如果 AI 依赖它，排除索引时 AI 也必须一起消失——「可插拔」就变成了「成对插拔」。
因此问答自己扫盘、自己分词：个人规模（数千条）下每次提问是毫秒级的 O(N)，与
`PersonDiary` 的读取方式一致。将来要提速，把 `AskEngine` 的输入换成索引查询即可，
冻结接口不变。

## 数据与隐私

- 不联网、无 `INTERNET` 权限；问题与检索结果只存在于内存。
- 人格快照以 `source: meteor-ai` 写入档案，和用户手写内容在同一层，可见、可删、可备份。
- 日志只记录成功/失败，不记录问题原文与检索到的正文——沿用 `AppLog` 的既有约定。
- 人格是**推算**，不是事实：界面会显示生成时间，并且「固化」是显式动作，不会偷偷写盘。

## 后果

- v0.6 没有「大模型自由对话」，只有基于原文的检索式问答；换来的是可离线、可验证、
  不泄密，且结果永远带出处。
- 若将来要引入云端模型：新增 `AiEngine` 实现、设置页密钥输入与明确的二次确认，
  冻结接口不动，但必须再写一份 ADR 说明数据出口。
- `:feature-settings` 的 `aiEnabled` 默认值改为 `true`（纯本机能力，没有隐私代价）；
  这个开关只控制首页入口是否显示，不改变数据。
