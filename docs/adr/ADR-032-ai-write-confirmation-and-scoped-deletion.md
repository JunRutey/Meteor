# ADR-032 · AI 写操作确认规则与受限删除

> 人物档案的删除能力与标签参数由 [ADR-034](ADR-034-person-deletion-custom-tags-and-detail-redesign.md) 补充。

- 状态：已接受
- 日期：2026-11-06
- 关联：ADR-027（联网 AI 与隐私边界）、ADR-030（工具权限与调用规范化）

## 背景

此前所有 AI 写工具都要求逐次确认，但这会打断低风险的追加和建档操作。用户希望仅对重要内容的覆盖、修改和删除确认，同时开放 AI 删除工具，但不能给予任意文件删除能力。此外，AI 心情工具遗漏了第七种心情；AI 修改心情后，日历返回主界面时也可能仍显示旧状态。

## 决定

### 工具与确认边界

| 工具 | 需要权限 | 每次确认 |
|---|---|---|
| `append_diary` | 写日记 | 否 |
| `set_mood` | 写日记 | 否 |
| `create_person` | 写人物 | 否 |
| `save_diary`（覆盖日记） | 写日记 | 是 |
| `update_person` | 写人物 | 是 |
| `delete_record` | 写日记 | 是 |

未提供确认处理器时，需确认的工具仍然拒绝执行。所有工具继续受能力登记、细分权限、参数校验与人物作用域约束。

### 受限删除

`delete_record` 仅接受 `record_type`（`diary` 或 `mood`）和 ISO 日期；不接受路径、记录 ID、人物档案或附件。每次调用都必须通过应用确认界面。删除能力通过 `:core-storage` 的窄接口提供，AI 模块只获得按类型和日期删除记录的操作，不获得任意文件访问能力。

### 心情与界面同步

`set_mood` 接受现有七种心情值。日历恢复刷新时重新加载当前月份的心情，使 AI 写入后回到主界面能显示最新值。

### R1 模块准入五问

1. **模块归属：** 删除接口归入既有 `:core-storage`，AI 工具归入既有 `:feature-ai`；不新增模块。
2. **依赖方向：** `:feature-ai` 依赖窄存储接口，`:app` 负责向 AI 组装实现；方向单向、无环。
3. **对外接口：** `ArchiveRecordDeleter.delete(type, date)` 只暴露日记/心情类型与日期，没有任意路径或文件句柄。
4. **可移除性：** 移除 AI 后，存储和既有档案数据仍可独立使用；无数据迁移。
5. **数据格式：** 不改变持久化格式；删除目标按既有日期目录定位，既有数据保持兼容。

## 后果

- 常规追加、心情写入和人物建档不被确认弹窗打断；覆盖、人物修改和删除保留明确确认。
- AI 删除的能力面被限制为指定日期的日记或心情，且不可绕过每次确认。
- 新增能力依赖只存在于应用组装层，不修改冻结接口。
