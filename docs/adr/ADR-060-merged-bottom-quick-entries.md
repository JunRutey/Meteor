# ADR-060 · 底部快捷入口合并：相册与记录一个图标

> 状态：已采纳。关联：[ADR-054](ADR-054-album-hub-and-sort-toggle.md)（相册总入口）、
> [ADR-052](ADR-052-media-album-hub.md)（媒体与选择器）。

## 一、问题

ADR-054 把「记录」并进了相册总入口（内部「相册 / 记录」两段），但日记主页底部的
快捷区仍是三个方块：

| 方块 | 实际去向 |
|---|---|
| 图片总览 | 相册总入口 |
| 记录 | 相册总入口（同一页） |
| 人际关系 | 人物列表 |

也就是说，**两个图标指向同一个页面**，而且第一个还叫旧名字「图片总览」。
对用户来说这是重复入口，也看不出「记录」已经并入相册。

## 二、决策

1. **合并为两个入口**：底部快捷区只保留
   - **相册** → 相册总入口（图片 / 视频 / 音频 / 记录都在里面）；
   - **人际关系** → 人物列表。
2. **合并图标**：新增 `AlbumGlyph`，画两张叠放的卡片，前一张带照片标记
   （太阳 + 山形）。前卡代表照片/视频，后卡代表叠在后面的记录，一个图标同时
   表达「相册 + 记录」。
3. **重设计布局**：三个竖排小方块改为两个等宽横排卡片：
   - 高度 72dp，图标放在 40dp 的主色浅色方块里；
   - 标题 + 一行副标题（「图片 · 视频 · 记录」/「人物档案」），副标题超长省略；
   - 底部分别为 `calendar_open_gallery`（值改为「相册」）与
     `calendar_open_people`（「人际关系」）。
4. **接口收敛**：`CalendarScreen` 的 `onOpenGallery` / `onOpenChats` 合并成一个
   `onOpenAlbum`；`calendar_open_chats` 文案删除。独立路由 `chats` 保留（深链兼容），
   但界面不再有单独入口。

## 三、R1 四问

1. **模块**：只改 `:feature-calendar` 的 UI 与 `:app` 的导航参数，不新增模块。
2. **依赖**：无新增模块边。
3. **接口**：`CalendarScreen` 的两个入口回调合并为一个；该模块不在 R2 冻结列表内，
   调用方只有 `:app` 一处，同步修改。
4. **数据格式**：无变化。纯界面调整。

## 四、后果

- 底部不再有两个指向同一页的入口，图标与文字都能反映「记录已并入相册」。
- 两个入口等宽横排，标题 + 副标题的层级比原来的单行小字更清楚。
- 旧的 `chats` 路由仍可被深链打开，不影响既有链接。
