# ADR-021 · 编辑器退回纯文本，加粗也下线

- 状态：已接受（v0.4）
- 影响：`:feature-editor`
- 取代：[ADR-019](ADR-019-editor-keeps-bold-images-links.md) 中「保留加粗」的部分

## 背景

ADR-019 砍掉颜色和斜体后，只剩加粗一种「隐藏标记」的样式。它带来的唯一收益是
打字时看着是粗体；代价却是整个编辑器里最脆弱的一块：

- 隐藏 4 个字符会让渲染文本变短，必须有真实的 `OffsetMapping`，
  第一版直接因为长度不一致在 Compose 崩溃过一次，后来又出现过光标跳位；
- 一份 `VisualTransformation`、一份偏移映射构建器、三份针对映射边界的测试，
  全都只为这一种样式存在；
- 只要还有一种隐藏标记，就必须永远维护这套映射。

而实际使用中，加粗对「记一件事」几乎没有信息增益：中文写作的强调通常靠句子本身，
加粗只影响观感。

## 决策

**编辑区是纯文本。工具栏只保留「链接」「图片」两项。**

- 删除 `EditorRendering`、`MarkdownStyledTransformation`、`toggleBold`、
  `wrapsWith`、`EditResult`，以及对应的测试；
- `MarkdownField` 的输入框回到普通 `OutlinedTextField`，
  只保留一份本地草稿（避免中文 IME 每次按键都绕一圈 ViewModel 而卡顿）；
- `MarkdownStyles` 继续做预览解析：`**粗**`、`*斜*`、`<span>` 都能正常显示。

## 兼容

已经写在正文里的 `**…**` 不做迁移：编辑区按字面显示（可以删），预览照常渲染成粗体。
这与 ADR-019 处理颜色/斜体的方式一致——**不再支持写入，但永不假装看不见**。

## 后果

- 编辑器里不存在「隐藏字符」，因此不存在光标映射这个 bug 类别；
- 新增样式的正确路径变成「只做预览渲染，不做编辑期隐藏」；
- 工具栏现在只有 3 个动作，未来加任何格式（标题、列表）都应该是**插入语法**，
  而不是隐藏语法。
