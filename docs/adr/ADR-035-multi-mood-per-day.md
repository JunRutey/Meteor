# ADR-035 · 一天最多三个心情，正文多行编码

- 状态：已接受
- 影响：`:core-storage`、`:feature-calendar`、`:feature-ai`、`:app`（搜索索引）

## 一、问题

v0.3 起，一天只有一个心情：`时光轴/心情/<date>.md` 的正文是一个 `Mood.code`。
用户在心情日历上点选一个表情即替换当天心情，再点同一个只是重写同一个值，无法取消。

需求是：**一天最多同时记录三个心情；点选加入，再点同一个取消**。这要求存储、
状态模型和界面同时从「单值」变成「有序列表」，并且不能破坏已有档案。

## 二、存储格式

心情记录的正文改为**每行一个心情码**（`happy\ncalm\nexcited`），顺序即用户的
选择顺序。三处约束保证了不做数据迁移也能平滑升级：

1. 旧记录正文只有一个码（`happy`），按行解析后就是单元素列表；
2. 新版本不认识的码在解析时被忽略，不会让整天的记录失效；
3. 只有一个心情时写出的正文与旧格式完全相同，旧版本仍能正常读取。

只选了一个心情时写回单行，旧版本继续可读；选了多个时旧版本会把它当作未知码，
按既有约定显示「没有心情」，不会崩溃。这是 ADR-017「新增常量双向向后兼容」的延伸。

解析与编码集中在 `Mood.decode` / `Mood.encode`，上限 `Mood.MAX_PER_DAY = 3`
也在这一层强制：去重、截断，避免任何调用方写出第四行。清空最后一个心情时删除
该日文件，而不是留下一个空正文的 `type: mood` 记录——空记录会污染索引与统计。

`MoodQueries` 的返回类型随之从 `Map<LocalDate, Mood>` / `Mood?` 改为
`Map<LocalDate, List<Mood>>` / `List<Mood>`；`save` 接收列表，空列表表示删除。
`MoodQueries` 不在 `FROZEN INTERFACE` 列表中，`StorageRouter`、frontmatter 五字段
和路由规则都没有改动。

## 三、界面

- 日格：最多并排显示三个 emoji；单心情时保持原有字号。
- 选中日卡片：七个表情均可点，选中项高亮描边；再点已选中的表情即取消。
- 已选满三个时，未选中的表情降透明度并禁用，下方文案提示「已选 3/3 ·
  再点一次可取消」，说明为什么点不动。
- 卡片标题显示当天全部心情标签（如「今日心情 · 开心、平静」）。

## 四、连带改动

- **搜索索引**：心情记录原来只把单个码映射成标签；现在把每个码都映射成标签、
  以空格连接后写入索引。三个心情中的任意一个都能被搜到。
- **AI `read_moods`**：每天返回 `moods` 数组而不是单个 `mood`，模型能看到全部三个。
- **AI `set_mood`**：仍是单值工具，语义是「覆盖当天心情」，固定写成单元素列表。
  多心情主要由用户在手势界面上完成，没有扩大模型写权限的粒度。
- 取消最后一个心情后会从搜索索引删除该记录，避免搜索残留。

## 五、被否掉的方案

- **写进日记 frontmatter**：§5.1 冻结五个字段，且心情属于内容，不应进明文元数据。
- **正文用 JSON 数组**：可读性与解析成本都不如按行；旧记录也无法自然兼容。
- **一天拆成多个 mood 文件**：路由、索引、备份和删除接口都要改，收益为零。
- **不设上限**：界面一行放不下，且需求明确是三个。

## 六、兼容性与后续

- 不需要迁移脚本；备份导出的是解密后的 Markdown，正文换行天然保留。
- 旧版本遇到多心情记录显示「无心情」，建议在发布说明的「已知限制」中写明。
- 若将来要调整上限，只改 `Mood.MAX_PER_DAY` 与文案；存储格式不用变。
