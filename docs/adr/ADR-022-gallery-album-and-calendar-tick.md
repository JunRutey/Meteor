# ADR-022 · 相册按天分组并可长按删除；日历标记已写日记的日子

- 状态：已接受（v0.4）
- 影响：`:feature-gallery`、`:feature-calendar`、`:core-storage`、`:app`

## 一、相册：一天一个日期

原来的图片页把所有图排成一个 3 列网格，每张下面重复一遍同一个日期。
一天插五张图，就有五行一模一样的「2026年10月31日」，看不出哪张属于哪天。

**决策**：按图片落盘时间的**本地日期**分组，一天只在组头出现一次日期，
下面是这天所有图，3 列方形网格——与系统相册一致。

日期标签用本地化格式（`FormatStyle.MEDIUM`），不在代码里拼「M月d日」：
仓库规则是零硬编码中文，日期文案必须跟着系统语言走。

## 二、相册：长按选择，再删除

图片一旦插入就只能去日记里删，相册本身是只读的。用户在相册里看到一张废图，
没有任何办法处理它。

**决策**：

- **长按**任意图片进入多选，选中的图压一层半透明遮罩并打勾；
- 底部出现操作条：「已选 N 张 / 取消 / 删除」；
- 删除前二次确认，确认文案明确说明后果；
- 删除走 `ImageStore.delete`，删的是密文文件本身。

用 `pointerInput` + `detectTapGestures` 而不是 `combinedClickable`：
后者在 Compose 1.7 仍是实验 API，而本仓库不能本地编译验证 opt-in 注解。

**不做级联改写正文**：不扫描所有日记去删掉 `![](meteor://image/…)`。
那等于用户点一次删除就静默改写多条记录，风险远大于好处。
代价是那条日记里会显示「图片无法显示」——确认文案把这件事说清楚。

## 三、日历：哪天写过日记

心情日历只显示心情，看不出哪天其实已经写过日记。用户要先点进「查看当天日记」
才知道是空的还是要编辑。

**决策**：底部日期卡片里，若当天存在日记文件，就在日期后面画一个**绿色重叠双对勾**
（Canvas 画两条 check 路径，颜色 `#25D366`，不依赖字体里的 ✓ 字形）。

数据来自 `DiaryQueries.dates()`（一次目录遍历），进入页面和从编辑器返回时刷新。
它只表达「这天有记录」，不带已读/已送达那种即时通讯语义。

## 限制

- 相册一次最多加载 120 张（`MAX_ITEMS`），更多图需要分页，目前未做；
- 相册删除不清理引用，正文里会留下失效的 `meteor://image/<token>`；
- 分组用图片文件的修改时间，重新导入备份后分组可能变化（导入会重写文件）；
- 日历的 ✓✓ 只标「有日记」，不区分日记是否为空文本。
