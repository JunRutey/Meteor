# Meteor v1.3.2 · 冷启动更清晰，农历生日不再等

v1.3.2 是一个体验补丁：冷启动换成专用的高分辨率图标，农历生日在 Splash 阶段提前预热，首次进入生辰页不再对着转圈；人物关系里的家人 / 朋友 / 绝交的朋友也统一成可删除标签，并修掉了正文中文输入时编辑区被身份卡挤小的问题。本版不改变档案数据格式。

## 新增

- **冷启动专用图标**：新增强制透明的 1152×1152 启动图标，替代放大后发糊、且带白色方底的自适应启动图标；流星在浅色和深色纸张背景上都更清晰。
- **农历生日预加载**：冷启动时提前读取出生资料并完成农历「下一次生日」计算，首次进入生辰页直接显示结果，不再先出现加载圈。

## 修复

- 修复 Splash 图标模糊、深色背景上出现白色方卡的问题。
- 修复农历生日用户首次进入生辰页需要等待 ICU 换算的问题。
- 修复人物编辑页点击正文、中文输入法弹出后，身份卡仍占大量高度、正文输入框被压得很小的问题。

## 变更

- **关系标签统一**：家人 / 朋友 / 绝交的朋友不再作为不可删除的特殊芯片，和自定义标签一样带 × 与确认删除；「未分类」仍是清除选择，不参与删除。
- **默认标签**：三个关系标签首次使用时一次性种入标签库，删除后不会复活；新建人物默认「未分类」，不再默认选中「朋友」。
- **数据兼容**：`profile.md` 的 `relation:` 仍由选中的内置标签派生，删除后写 null；`tags:` 与 AI 工具兼容，数据格式不变。
- **正文输入布局**：正文获得焦点且输入法可见时，身份卡上限从 44% 平滑收缩到 18%，把高度让给正文；正文失焦或收起键盘后恢复。
- **Splash 等待策略**：冷启动会同时等待应用锁/引导状态与农历预热完成，保留 5 秒安全阀，避免异常时永久停在启动画面。

## 已知限制

- 不改变档案数据格式；旧日记、备份、人物档案、AI 会话与已保存的出生日期继续可用。
- 农历用户首次冷启动可能比原来多等约数百毫秒到 1–2 秒；5 秒安全阀会兜底放行。
- 预热在解锁前读取加密出生资料，但只在内存中准备、不渲染任何内容；应用锁仍是 UI 门禁，锁屏逻辑未改。
- `WindowInsets.isImeVisible` 仍是 Compose 实验 API；设备不报告 IME inset 时会回退到原来的 44% 行为。
- 默认标签按种子时的语言写入 DataStore，之后切换系统语言不会自动翻译已保存的标签。
- 备份恢复后若 `people_tags_seeded` 标记未随快照恢复，默认标签可能补种一次；不影响档案数据。
