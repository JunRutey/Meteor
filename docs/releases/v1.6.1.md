# Meteor v1.6.1 · 每日一问回到日卡片，更新不再静默下载

v1.6.1 是 v1.6.0 的小修订，两件事：

一是**把首页日卡片左按钮改回「每日一问」**。v1.6.0 把这个位置留给了「查看当天图片」，
但真正想提问的时候，入口反而多了一层。本版把「每日一问」放回日卡片左下角，点击直接进问题列表；
看某天的图片改从相册进。底部快捷入口也随之恢复为「相册 / 人际关系」两格。

二是**重做应用更新链路**：发现新版本不再静默后台下载，而是先弹窗询问；下载时在官方地址
与三个内置社区镜像之间按延迟挑最快的那个，并用 GitHub 公布的 SHA-256 校验整个 APK。

本版**不迁移任何既有数据**，档案格式、加密密钥与备份快照一个字节未动。1.6.0 的用户可以直接升级。

## 新增

**更新弹窗**

- 启动检查到新版本时先弹窗，给出三个回答：**立即更新**、**稍后再说**、**忽略此版本**。
  「忽略此版本」只对当前版本生效，安装新版后自动失效。
- 弹窗只在完成首启引导且已解锁之后出现，不会盖住锁屏或引导页。

**镜像择优与完整性校验**

- 下载前对「官方地址 + 三个内置镜像」并发探测延迟，按快慢依次尝试，某个源失败就换下一个。
- 内置镜像为 `gh-proxy.com`、`ghfast.top`、`ghproxy.net`，地址由应用本地从已校验的
  `github.com` 下载地址拼出，不采信第三方返回的链接。
- 无论从哪个源下载，APK 都必须与 GitHub Release 给出的 SHA-256 一致才会进入安装流程；
  不一致就删掉文件并报错。从上次启动留下的缓存 APK 也会先校验再复用。
- 「设置 → 应用更新」新增「发现新版本 / 下载更新」，可以在不等到下次启动的情况下立即下载。

## 修复

无。本版没有修复用户可感知的缺陷。

## 变更

**首页**

- 日卡片左下角的按钮从「查看当天图片」改回「每日一问」，点击进入问题列表。看某天的图片请从相册进，
  不再从日历直达。
- 底部快捷入口从「每日一问 / 相册 / 人际关系」恢复为「相册 / 人际关系」两格。

**应用更新**

- 发现新版本后**不再自动下载**，必须由你确认。检查本身、定时器与通知都不会触发下载。
- 下载进度通知只在确认下载、开始取字节后出现；「发现新版本」阶段不产生通知。
- 完整性判断从「文件大小 + ZIP 魔数」升级为官方 SHA-256。只有 GitHub 没给校验和的老版本
  Release 才退回旧判断，并写一条警告日志。

## 已知限制

- 镜像的可用性不由我们控制：社区公益服务可能随时失效，症状只是多一次回退；全部失效时
  退化为与旧版一致的直连行为。内置清单要更新就得发版。
- 下载前最多要等约 4 秒的延迟探测（四个源并发，各 4 秒超时，全部超时才等满）。
- 「忽略此版本」是设备本地状态：换机或清除数据后会重新询问，也不进备份。
- 更新只认 GitHub 正式 Release，PR 预发布不参与。
- 安装仍需允许 Meteor 安装未知来源应用，并由系统安装器确认。
- 本版没有新增自动化 UI 测试；更新源排序与元数据解析有单元测试。
