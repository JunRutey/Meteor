# Meteor v0.6.1 · AI 查档、用量与推理

## 新增

- **按时间查档案**：AI 现在能理解「今天 / 昨天 / 前天 / 本周 / 上周 / 这个月 / 上个月 /
  最近 N 天 / 2026-10-31 / 10月31日」这类说法，直接在对应日期范围里取记录；
  「某天写了什么」不再靠碰运气。
- **更多只读工具**：`read_diary(date)` 读某天日记、`list_diary_dates` 列出有日记的日期、
  `list_records(from,to)` 按日期过滤、`read_moods(days=N)` 读最近 N 天心情；
  再加上原有的检索、人物、单条记录，共 8 个只读工具。仍然没有写 / 删 / 导出能力。
- **系统提示带上档案概况**：当前日期、星期、最近与最早的日记日期、记录总数，
  模型不必先试错才知道有没有数据。
- **用量透明**：每条回答下方显示耗时、tokens、tok/s 与缓存命中率；输入框上方显示本次
  会话累计。数字来自提供商返回的 `usage`（DeepSeek 的
  `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 与 OpenAI 的
  `prompt_tokens_details.cached_tokens` 都做了归一化）。
- **思考档位**：设置里可选「自动 / 关闭 / 低 / 高 / 最高」。关闭发送
  `thinking.type=disabled`，档位发送 `thinking.type=enabled` + `reasoning_effort`；
  「自动」不发送任何额外参数，兼容性最好。该参数只对 DeepSeek 发送，避免其它兼容接口报错。
- **思维链回传**：带工具的思考请求会把 `reasoning_content` 回传，符合 DeepSeek 的工具调用要求。

## 变更

- **API Key 与日记共用同一把设备密钥**：凭据改成用 `core-crypto` 的 AES-256-GCM
  （与档案文件同一个 Keystore 别名）加密后存成 Base64 密文；旧版
  EncryptedSharedPreferences 里的 Key 会在首次读取时自动迁移并删除。仍然是设备绑定、
  不可导出、不进备份、不写日志。

## 修复

- 修正「问某一天」时模型误判「这一天没有记录」的问题（现在按日期取记录并附在上下文里）。

## 已知限制

- 思考档位只对 DeepSeek 生效；OpenAI 与自定义接口只发送「自动」。
- token 统计以提供商返回的 `usage` 为准；个别兼容接口不返回 usage 时，这一行不显示。
- 时间解析支持常见说法，不支持「上周三」这类需要二次推算的表达。
- 真实联网仍只能在设备上验证；CI 覆盖时间解析、协议、用量合并、思考参数与密钥加密。
