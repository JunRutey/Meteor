# Meteor v1.5.0 · 相册、媒体播放与大文件优化

v1.5.0 把「图片总览」升级为真正的**相册**：图片、视频、音频都能存放和播放，编辑器与人物档案同步支持。
本版还重做了大文件的导入与播放链路，并补上了删除日记、返回确认等日常操作。
**档案数据格式向后兼容**：旧日记、旧图片、旧媒体、人物档案、备份与 AI 会话继续可用。

## 新增

**相册（原「图片总览」）**

- 更名「相册」，支持**视频**与**音频**；网格带类型角标与视频时长
- 顶部可筛选「全部 / 图片 / 视频 / 音频」
- 点开即看即播：图片全屏缩放、视频全屏播放、音频带进度条播放
- 图片原有的分享与删除保留，视频与音频同样支持

**排序方式**

- 新增「排序方式」开关：**按源数据排序**（拍摄/录制时间）或**按存入日期排序**
- 默认仍是存入日期，与旧版本表现一致

**应用内文件选择器**

- 设置 → 媒体 → 文件选择器：可在**内置**与**系统**之间切换，默认内置
- 内置选择器是**独立页面**，不再覆盖在编辑界面之上
- 内置选择器**音频按列表显示**：文件名、时长、大小一目了然
- 选择器保留源文件元数据（EXIF 拍摄时间、视频/音频时长与尺寸）

**编辑器**

- 工具栏「插入」支持图片 / 视频 / 音频；正文里显示为图片块、可播视频卡或音频卡
- 音频卡显示**原始文件名**
- 视频支持**横向全屏**播放（退出后自动恢复方向）
- **大文件先占位、后台加密**：选完立即出现「正在导入…」卡片，可以继续写、继续添加文件
- **返回确认**：有未保存内容时，系统返回或页头返回先弹窗，可选「确认返回」或「保存并返回」
- **删除当天日记**：页头删除入口，二次确认后删除该天日记记录；正文里的图片与媒体不会被删除

**人际关系**

- 人物详情页新增「媒体」区，展示这个人的图片、视频与音频，点开即可查看或播放
- 「添加媒体」直接归档到该人物名下；人物正文也可插入媒体

**记录页并入相册**

- 原来的「记录」与「相册」合并为一个总入口，内部用「相册 / 记录」两段切换
- 日记主页底部快捷区简化为「相册」与「人际关系」两个入口

**备份**

- 明文备份现在包含视频与音频，并写入媒体清单；换机恢复后**媒体编号与拍摄时间不变**
- 没有媒体的旧备份结构完全不变

**性能与存储**

- 加密分块提升到 10 MiB，减少大文件加密时的系统调用次数
- 媒体改用 **Keystore 包裹的二级密钥**加解密，并支持并行处理，大幅缩短大视频导入/播放等待
- 播放改为**流式解密**：点开只需解密开头，不再先把整份文件解密成临时文件
- **内容哈希去重**：同一文件在不同板块只存一份，正文引用共享
- 进程内缓存 Keystore 密钥句柄，减少重复读取

## 修复

- 日记预览页的媒体卡片一直显示「正在载入」（预览页没有接上媒体解析）
- 人物详情页正文里的媒体卡片不显示（媒体解析从未被触发）
- 预览页把未闭合的颜色标签当作普通文字显示（与编辑页渲染不一致）
- 相册与记录入口重复：两个图标指向同一页面
- 从媒体选择器返回后编辑页被遮挡的问题（选择器改为独立页面）

## 变更

- 首页入口文案由「图片」改为「相册」；日历页图片入口自动转到新相册与查看器
- 视频播放使用 AndroidX **Media3 / ExoPlayer**；**没有引入 FFmpeg**（ffmpeg-kit 已停止维护，体积代价大，本场景平台能力已覆盖）
- 媒体文件格式升级：新导入媒体使用新格式（含二级密钥），旧媒体继续可读；**旧版本客户端读取新版媒体会明确报错**
- 旋转屏幕不再重建页面（为全屏视频保持播放器），界面由 Compose 重新布局
- 明文备份体积会因视频与音频明显变大

## 已知限制

- 按源数据排序依赖文件自带的时间：没有 EXIF 拍摄时间的老照片会退回按存入日期排列
- 分享媒体时仍会临时解密一份文件交给系统分享（分享结束即删除）；播放本身不再产生明文副本
- 删除媒体是永久删除，引用过它的正文不会自动改写，对应位置显示「无法显示」
- 内容去重是全局的：媒体保持**首次导入时的归属**，人物的「媒体」区可能只显示首次归属的那一份，但正文引用正常
- 媒体二级密钥保存在应用私有目录，卸载应用即丢失；换机仍依赖明文备份恢复
- 首次导入很大的视频仍需要一段复制与加密时间（已明显缩短），期间显示「正在导入…」
- 正文里还有「正在导入…」的卡片时不能保存，等它完成即可；离开编辑页会取消尚未完成的导入
- 旧版本客户端读新备份时会看到无法识别的媒体清单文件；升级后可恢复
