# Meteor v1.1.0 · 日志覆盖更完整，导出位置由你决定

v1.1.0 围绕「出问题时能查清楚」打磨诊断能力：应用日志覆盖更多关键操作，普通会话也能看到
出错前的操作路径；导出日志改由系统文件选择器决定保存位置，不再固定写进 Download。
出生日期滚轮也顺手修了首次打开闪跳与点击瞬移的问题。本版不改变数据格式，
旧日记、备份、人物档案、AI 会话与已保存的出生日期继续可用。

## 新增

- **导出日志可选择保存位置**：设置 → 诊断 → 「导出日志…」会打开系统文件选择器，
  可以保存到下载、云盘、U 盘或任意支持的位置，并可修改文件名。任何 Android 版本都不再
  需要存储权限，也不再固定写入 `Download/Meteor/`。
- **日志覆盖更多关键操作**：新增进程启动与 Activity 前后台、设置项变更、更新检查/下载/安装、
  AI 对话摘要、附件导入、引导完成等事件。普通会话默认记录 INFO 及以上级别；
  「调试日志」开关只决定是否额外记录 DEBUG 细节。
- **导出内容更适合排查**：导出文件头包含应用版本、构建类型、包名、设备型号与 API、
  ABI、语言、时区与调试日志状态；日志正文按文件分区，优先保留最新内容。

## 修复

- 修复出生日期滚轮首次打开时从顶部闪跳、长距离滚动到已选日期的问题；列表重建时同样
  瞬时定位，点选某一项后才平滑滚回中间。
- 修复导出日志时可能截断半行、日志过大导致内存压力的问题：按行读取每个日志文件的尾部，
  并限制单文件与总长度。
- 修复日志文件写入失败被静默吞掉的问题：写入失败会回退到 Logcat，仍可通过
  `adb logcat` 排查。
- 修复更新流程中非预期协程异常可能直接导致应用崩溃的问题：现在会写入日志并显示为
  普通下载失败。
- 修复导出日志失败时提示过于笼统的问题：现在区分「无法打开所选位置 / 写入失败 /
  读取本机日志失败」。

## 变更

- **日志级别策略调整**：INFO / WARN / ERROR 默认写入文件，只有 DEBUG 受「调试日志」
  开关控制；设置页说明已同步更新。
- **日志清理策略**：仍按 7 天保留，同时增加 32 MB 总大小上限，超出后按最旧文件优先清理，
  当天正在写入的文件始终保留。
- **导出入口**：由系统文件选择器接管保存位置与文件名，导出成功后显示实际文件名。
- **日志开关文案**：从「关闭时仅记录警告与错误」改为「关闭时仍保留关键操作与错误」，
  与实际行为一致。

## 已知限制

- 不改变数据格式；旧日记、备份、人物档案、AI 会话与已保存的出生日期继续可用。
- 日志仍只保留最近 7 天，并受 32 MB 总大小限制；更早的日志会被自动清理，
  重要日志请及时导出。
- 关闭「调试日志」时不会记录 DEBUG 细节；需要更细的排查信息时，请在设置中开启后
  复现问题再导出。
- 能否保存到云盘、外部存储或 U 盘取决于设备上已安装的文件提供器；个别第三方文件管理器
  可能不支持直接写入。
- 日志按设计不记录日记正文、附件内容或 API Key，但会包含设备信息、应用版本与操作事件；
  分享前请自行确认。
- 自动更新只认 GitHub 正式 Release；安装仍需允许「安装未知来源应用」并由系统安装器确认，
  部分设备或安全软件会拦截。
- 出生日期农历换算依赖设备 ICU 日历数据，个别旧系统可能缺少闰月信息；
  滚轮一次只调整一列。
