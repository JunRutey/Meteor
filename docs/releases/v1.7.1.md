# Meteor v1.7.1 · 更新进度留在眼前，设置不再多一条

v1.7.1 只改应用更新这一条链路。

以前点「立即更新」后弹窗立刻消失，下载进度只能在通知栏里看；如果通知被系统折叠，
很容易以为没有反应。这次让弹窗**原地变成进度条**：下载就在眼前，进度跑完时如果
弹窗还在前台，会直接拉起系统安装器。

同一个确认弹窗里还多了一块**固定高度的更新日志区域**：本次版本的说明从 GitHub Release
读取，太长就在区域里滑动查看，不会把弹窗撑满屏幕，也不会把「立即更新」等按钮挤出视野。

想先做别的事也没关系：点「后台下载」、按返回键或直接离开应用，弹窗就会收起，
下载继续在通知栏里进行，完成后再从通知或设置里安装。

设置里的「应用更新」也少了一条：发现新版本不再常驻第三个「下载更新」条目。
关掉启动弹窗后，再点一次「检查更新」就会重新弹窗；有新版本时立即询问，而不是
留一条需要用户自己找的入口。

本版**不迁移任何既有数据**，档案格式、加密密钥与备份快照均未改动。

## 新增

- **更新弹窗显示更新日志**：确认弹窗前增加固定高度、可滑动的「更新内容」区域，内容取自 GitHub Release 说明；没有说明时显示占位文案。
- **更新进度弹窗**：确认更新后，原弹窗变成前台进度条，显示当前版本、下载百分比与完成状态。
- **前台完成自动安装**：下载完成时如果进度弹窗仍在前台，自动打开系统安装器；校验不过或
  下载失败时弹窗关闭，不留下一条停在 99% 的进度条。
- **后台下载回退**：点「后台下载」、按返回键或离开应用，弹窗收起并继续由通知栏展示进度。

## 修复

- 修复「稍后再说」关掉启动弹窗后，进入设置只能看到一条常驻的「发现新版本 / 下载更新」
  条目、无法再次触发弹窗的问题。现在手动点「检查更新」会重新弹窗。

## 变更

- **设置 → 应用更新**移除第三个「下载更新」条目及其代码；状态行与「检查更新」按钮保留。
- 手动检查更新时会重新询问当前新版本；自动启动检查仍遵守「稍后再说」，不会反复打扰。
- 下载完成后若弹窗已收起，仍可从就绪通知或设置里的「安装更新」进入安装。

## 已知限制

- 只有进度弹窗保持在前台时才会自动拉起安装器；已经切到后台的下载需要手动点通知或设置里的
  「安装更新」。
- 安装仍需允许 Meteor 安装未知来源应用，并由系统安装器确认。
- 进度数字取决于下载源是否返回文件大小；未知大小时显示不确定进度条。
- 下载失败后不会自动重试，需要再次点「检查更新」。
- 更新日志来自 GitHub Release 的正文；离线或 Release 未填写正文时只显示「本次更新没有提供说明」。
- 更新日志按纯文本渲染，Markdown 的加粗、列表符号会尽量清理，但表格与图片不会还原成富文本。
